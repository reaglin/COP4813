Introduction to Responsive Web Design

Introduction

Responsive web design is the practice of building a single website that adapts gracefully to whatever screen it lands on — a phone held in one hand, a tablet in landscape, a laptop, or a large desktop monitor. Instead of maintaining separate "mobile" and "desktop" sites, you write one set of HTML and CSS that reflows, resizes, and reorganizes itself based on the available viewport. This introductory topic sets up the vocabulary and mental model you will use for the rest of the module: the multi-device landscape, the three core pillars (fluid grids, flexible images, and media queries), the mobile-first philosophy, and the viewport meta tag that makes any of it work on real phones.

Why does this matter in COP4813? Most of your users will reach your web applications from a mobile device first, and search engines, accessibility guidelines, and employers all assume responsive behavior as a baseline rather than a bonus. Understanding the "why" before the "how" will make the CSS you write later in the module — relative units, Flexbox and Grid, srcset, min-width media queries — feel like deliberate choices instead of memorized syntax.

As you watch the videos below, look for three things: how content is prioritized when space shrinks, how layouts are allowed to flex rather than being pinned to fixed pixel widths, and how designers think about breakpoints as content-driven decisions rather than device-specific ones. The first video is a hands-on tour of responsive layout mechanics in a visual tool; the two Apple sessions widen the lens to design thinking across an increasingly varied set of devices and form factors.

Fluid Grids and Flexible Layouts

Introduction

A fluid grid is the structural backbone of a responsive page. Instead of fixing column widths in pixels, you express them as proportions of their container — percentages, fr units, em and rem — so the layout reflows and rescales continuously as the viewport changes. The classic conversion formula (target divided by context equals result) lets you take an existing fixed-width comp and translate each column and gutter into a relative value that preserves the original proportions.

In this module, fluid grids are one of the three pillars of responsive design, alongside flexible images and media queries. Modern CSS gives you two purpose-built layout modules for the job: Flexbox, which distributes space along a single axis and is ideal for navigation bars, card rows, and component-level alignment, and CSS Grid, which defines rows and columns together for full two-dimensional page structure. You also need to understand how padding, borders, and gutters interact with percentage widths — which is why box-sizing: border-box and the gap property matter so much in fluid layouts.

As you watch the videos below, focus on three things: which unit or layout method the presenter chooses and why, how spacing between items is created (margins versus gap), and how the layout behaves when the browser window is resized. Try rebuilding each example yourself and then drag your browser edge or use DevTools device emulation to verify that nothing overflows, collapses, or breaks at in-between widths.

Flexible Images and Media

Introduction

Flexible images and media are the second pillar of responsive web design. A fluid grid will happily shrink and stretch, but a fixed-width image dropped into that grid will overflow its container, trigger horizontal scrolling, or force the layout to break. The classic fix is deceptively simple — a CSS rule such as img { max-width: 100%; height: auto; } — but modern responsive media goes further, letting the browser choose among several image files based on screen width and pixel density, and letting you swap in a differently cropped image for narrow screens.

In this topic you will work through the max-width technique, the srcset and sizes attributes on the img element, the picture element with source and media for art direction, techniques for keeping embedded video and iframes fluid, and the CSS background-size property (cover, contain, and percentage values) for responsive background images. Running underneath all of it is a performance question: mobile users on slow connections should not download a 2000-pixel-wide hero image to display it at 400 pixels.

As you watch, pay attention to three things. First, the difference between resolution switching (same picture, different file sizes — srcset and sizes) and art direction (different crops or compositions — the picture element). Second, how the sizes attribute tells the browser how wide the image will be laid out, since the browser must decide which file to download before the CSS is fully applied. Third, note the actual markup and CSS syntax so you can reproduce it, not just recognize it.

CSS Media Queries

Introduction

CSS media queries are the conditional logic of styling: they let you apply a block of CSS only when the browsing context matches certain conditions, such as a minimum viewport width, a landscape orientation, or a device that supports hover. Without them, a single stylesheet must serve every screen identically; with them, the same HTML can present a single-column mobile layout, a two-column tablet layout, and a wide desktop layout.

In this module, media queries are the third pillar of responsive design, working alongside fluid grids and flexible images. Fluid layouts handle continuous scaling between sizes; media queries handle the moments where the layout needs to change shape entirely — collapsing a navigation bar, stacking cards, or hiding a sidebar. You will also look at where media queries live (inside an external stylesheet, in a linked file, or via the media attribute) and how a mobile-first approach using min-width differs from a desktop-first approach using max-width.

As you watch, pay attention to four things: the exact syntax of the @media rule and its media type and feature conditions; how breakpoint values are chosen and whether the instructor argues from content or from device names; how the cascade determines which rule wins when two media queries both match; and how each demo is tested, usually with browser developer tools and device emulation. Try re-typing the examples yourself and resizing the window rather than only watching.

Mobile-First Design Philosophy

Introduction

Mobile-first design means starting your layout, content decisions, and CSS with the smallest screen in mind, then adding complexity as more space becomes available. Instead of building a full desktop page and stripping things away for phones, you begin with the essential content and a single-column layout, and use min-width media queries to progressively enhance the design for tablets and desktops. This forces hard choices early: what content truly matters, what can wait, and what is decoration.

This approach matters in COP4813 because most real-world traffic arrives on phones over variable networks. Mobile-first thinking tends to produce leaner CSS, faster initial loads, and a clearer content hierarchy, and it pairs naturally with progressive enhancement — delivering a working baseline experience to every browser and layering on features where they are supported. It also changes how you reason about breakpoints: you add rules as the viewport grows rather than overriding desktop assumptions downward.

As you watch the videos below, look for three things. First, how progressive enhancement is framed as a baseline-plus-layers strategy rather than an all-or-nothing feature choice. Second, how responsive utility classes or media queries express the idea of "small screen first, larger screens as overrides." Third, the professional mindset behind these choices — the habits and reasoning that lead developers to design for constraints first.

Viewport Configuration and Screen Sizes

Introduction

Every browser renders a page inside a viewport — the visible area available for your content. On desktop machines that area is usually close to the window size, but on phones and tablets browsers historically pretended to be much wider so that older desktop-only sites would still fit. The viewport meta tag is how you tell a mobile browser to stop pretending: it sets the layout width to the device width and establishes the initial zoom level. Without it, even carefully written responsive CSS will appear shrunken and unreadable on a phone.

Once the viewport is configured correctly, the next question is where your layout should change. CSS breakpoints are the specific viewport widths at which you introduce new rules through media queries — stacking columns, resizing type, hiding or revealing navigation. Breakpoints are best chosen by watching where your own content starts to break rather than by memorizing a list of device widths, since the range of real screen sizes is continuous and constantly shifting. You will also decide on a direction: mobile-first, which starts with a simple small-screen layout and adds complexity using min-width queries, or desktop-first, which starts wide and strips down using max-width queries.

As you watch the videos below, pay attention to three things: the exact syntax of a media query and where it sits in your stylesheet, how the order of rules determines which styles win when several queries match, and how the presenters decide that a layout needs a breakpoint at all. Afterward, practice testing your own pages by resizing the browser window and using your browser's device emulation tools at several widths, not just one or two.

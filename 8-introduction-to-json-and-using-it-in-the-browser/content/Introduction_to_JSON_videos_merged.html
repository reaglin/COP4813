What is JSON?

Introduction

JSON, short for JavaScript Object Notation, is a lightweight text format for representing structured data. It grew out of JavaScript's object literal syntax, but it is now a language-independent standard that servers, browsers, mobile apps, and APIs all use to exchange information. When a web page asks a server for data, the response you receive is very often a JSON string.

In this course, JSON is the bridge between the server and the browser. Before you can fetch data with the Fetch API or XMLHttpRequest and render it on a page, you need to be comfortable reading JSON, recognizing valid syntax, and understanding exactly how a JSON string differs from a live JavaScript object in memory. That distinction is what makes JSON.parse() and JSON.stringify() necessary rather than optional.

As you watch the videos below, pay attention to the small syntax rules that trip people up: double quotes around every key, commas between members but never after the last one, and the limited set of allowed value types (string, number, boolean, null, object, array). Also watch for how objects and arrays nest inside one another, since real API responses are usually several levels deep.

JSON Syntax and Structure

Introduction

JSON (JavaScript Object Notation) is a lightweight, text-based format for representing structured data. It was derived from the object literal syntax of JavaScript, but it is language-independent: virtually every modern programming environment can read and write it. In web development, JSON is the format you will most often encounter when a browser requests data from an API, when configuration files are stored, or when data is passed between a client and a server.

In this course, JSON matters because the rest of the module builds directly on it. Before you can fetch data from a remote source, parse it, loop through it, and render it into the DOM, you need to be able to read a JSON document confidently and recognize whether it is valid. That means knowing the six permitted value types (string, number, boolean, null, object, array), understanding that keys must be double-quoted strings, and being comfortable with structures that nest objects inside arrays inside objects, sometimes several levels deep.

As you watch the videos below, pay close attention to the small syntax details that trip people up: double quotes rather than single quotes, no trailing commas, no comments, and the distinction between a JSON text (a string) and a JavaScript object in memory. Also notice how each presenter describes the shape of the data — "an array of objects," for example — because being able to name a structure out loud is the first step toward writing code that traverses it.

Parsing JSON in JavaScript

Introduction

JSON (JavaScript Object Notation) is a text format for representing structured data. When data arrives from a web API, a configuration file, or browser storage, it arrives as a string — not as a usable JavaScript object. Parsing is the step that bridges that gap: JSON.parse() reads a JSON-formatted string and returns the corresponding JavaScript value, whether that is an object, an array, a number, a string, a boolean, or null.

Because parsing depends entirely on the input being well-formed, this topic also covers what counts as valid JSON: double-quoted keys and strings, no trailing commas, no comments, no functions or undefined values, and correct nesting of objects and arrays. When the string is malformed, JSON.parse() throws a SyntaxError, so wrapping the call in try...catch is the standard defensive pattern. You will also meet the optional second argument to JSON.parse(), the reviver function, which lets you transform values as they are read — for example, converting an ISO date string into a real Date object.

As you watch, pay attention to three things: the distinction between a JSON string and a live JavaScript object, exactly which characters make a string invalid, and how parsed arrays can then be looped over with ordinary JavaScript. These habits carry directly into the fetch-and-render work later in this module.

Stringifying JavaScript Objects to JSON

Introduction

JavaScript objects live in memory, but the network, browser storage, and most server APIs only move text. JSON.stringify() is the bridge: it serializes a JavaScript value — an object, array, number, string, boolean, or null — into a JSON-formatted string that can be sent in a request body, saved to localStorage, or logged for inspection. It is the exact counterpart of JSON.parse(), which turns such a string back into a usable object.

In this topic you will look at the method's signature, JSON.stringify(value, replacer, space), and what each argument does. The optional replacer (a function or an array of property names) lets you filter or transform what gets written, and the space argument lets you pretty-print the output with indentation so it is readable during debugging. You will also see how different data types are treated: strings, numbers, booleans, arrays, and nested objects convert cleanly, while functions and undefined values are dropped from objects, and Date objects become ISO strings.

As you watch the videos below, keep one distinction in front of you: a JavaScript object is a live value you can access with dot notation, while the result of JSON.stringify() is just text. Notice when the speaker types quotes around the output in the console, and try to predict what each example will print before it appears on screen.

Fetching JSON Data with the Fetch API

Introduction

Most modern web applications do not ship all of their data inside the HTML page. Instead, the page loads first and then asks a server for data — usually formatted as JSON — and builds part of the interface from what comes back. The Fetch API is the standard, promise-based way to make that request from JavaScript in the browser. You call fetch() with a URL, receive a Response object, convert its body to a JavaScript object with .json(), and then do something useful with the result.

This topic ties together the earlier parts of the module. Knowing JSON syntax and the difference between a JSON string and a JavaScript object matters precisely because fetch() hands you text that must be parsed before you can loop over it or read its properties. You also need to think about what happens when things go wrong: a server may be unreachable, a URL may be wrong, or a response may come back with a 404 or 500 status. Fetch does not reject on HTTP error statuses, so checking response.ok and wrapping await calls in try/catch are habits worth forming now.

As you watch, pay attention to three things: the shape of a basic fetch chain (fetch, then .json(), then use the data), how the same logic reads when rewritten with async/await, and how the parsed data is iterated and inserted into the DOM. Try typing the examples yourself against a public test API rather than only watching — the timing and ordering of asynchronous code is much easier to understand once you have seen it run.

Fetching JSON Data with XMLHttpRequest

Introduction

Before the Fetch API became standard, nearly all browser-based requests for data were made with XMLHttpRequest, usually shortened to XHR. It is a built-in browser object that lets JavaScript ask a server for a resource — often a JSON file or an API endpoint — without reloading the page. You create an XHR object, open it with an HTTP method and a URL, attach a handler that runs when the response arrives, and then send the request. Because the response arrives as text, you still need JSON.parse() to turn it into a usable JavaScript object or array.

XHR matters in this course for two reasons. First, you will encounter it constantly in existing codebases, tutorials, and older libraries, so you need to be able to read and maintain it. Second, comparing XHR to Fetch sharpens your understanding of what Fetch actually gives you: promises and async/await instead of event handlers and readyState checks, cleaner chaining, and a more predictable structure. Knowing both lets you make an informed choice rather than copying whatever you saw first.

As you watch the videos below, pay attention to the order of the steps (create, open, set a handler, send), to where the response text is converted into an object, and to how status codes and network failures are checked. Notice also how the same task looks when written with Fetch, and keep a short list of the differences you spot — you will need that comparison later in the module.

Displaying JSON Data in a Web Page

Introduction

Fetching JSON is only half the job. Once the data arrives, it exists only as values in memory — nothing appears on screen until you write code that turns those values into HTML the browser can display. This topic covers that final step: selecting a container element on the page to act as a render target, parsing the fetched response into a JavaScript object or array, and then generating markup from it.

There are two common ways to produce that markup. You can build an HTML string (often with template literals) and assign it to an element's innerHTML, or you can create nodes programmatically with methods such as document.createElement, set their text and attributes, and append them to the page. Both work; each has trade-offs in readability, performance, and safety when the data comes from an untrusted source. Because JSON data is usually an array of records, you will almost always combine one of these techniques with a loop so that one row, card, or list item is generated per item.

As you watch, pay attention to three things: where in the code the author grabs the target element, how the parsed data is looped over, and how the generated markup actually gets attached to the document. Also notice what happens when the data changes — whether the code clears and rebuilds the container or appends to what is already there. Those patterns are exactly what you will reuse in your own assignment code.

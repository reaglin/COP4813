Introduction

Most modern web applications do not ship all of their data inside the HTML page. Instead, the page loads first and then asks a server for data — usually formatted as JSON — and builds part of the interface from what comes back. The Fetch API is the standard, promise-based way to make that request from JavaScript in the browser. You call fetch() with a URL, receive a Response object, convert its body to a JavaScript object with .json(), and then do something useful with the result.

This topic ties together the earlier parts of the module. Knowing JSON syntax and the difference between a JSON string and a JavaScript object matters precisely because fetch() hands you text that must be parsed before you can loop over it or read its properties. You also need to think about what happens when things go wrong: a server may be unreachable, a URL may be wrong, or a response may come back with a 404 or 500 status. Fetch does not reject on HTTP error statuses, so checking response.ok and wrapping await calls in try/catch are habits worth forming now.

As you watch, pay attention to three things: the shape of a basic fetch chain (fetch, then .json(), then use the data), how the same logic reads when rewritten with async/await, and how the parsed data is iterated and inserted into the DOM. Try typing the examples yourself against a public test API rather than only watching — the timing and ordering of asynchronous code is much easier to understand once you have seen it run.

Introduction

Before the Fetch API became standard, nearly all browser-based requests for data were made with XMLHttpRequest, usually shortened to XHR. It is a built-in browser object that lets JavaScript ask a server for a resource — often a JSON file or an API endpoint — without reloading the page. You create an XHR object, open it with an HTTP method and a URL, attach a handler that runs when the response arrives, and then send the request. Because the response arrives as text, you still need JSON.parse() to turn it into a usable JavaScript object or array.

XHR matters in this course for two reasons. First, you will encounter it constantly in existing codebases, tutorials, and older libraries, so you need to be able to read and maintain it. Second, comparing XHR to Fetch sharpens your understanding of what Fetch actually gives you: promises and async/await instead of event handlers and readyState checks, cleaner chaining, and a more predictable structure. Knowing both lets you make an informed choice rather than copying whatever you saw first.

As you watch the videos below, pay attention to the order of the steps (create, open, set a handler, send), to where the response text is converted into an object, and to how status codes and network failures are checked. Notice also how the same task looks when written with Fetch, and keep a short list of the differences you spot — you will need that comparison later in the module.

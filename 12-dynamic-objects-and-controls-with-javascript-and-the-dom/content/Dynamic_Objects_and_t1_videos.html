Introduction

When a browser loads an HTML file, it does not simply display the markup — it builds an in-memory model of the page called the Document Object Model, or DOM. The DOM represents every element, attribute, and piece of text as a node in a tree, and it exposes those nodes to JavaScript as objects with properties and methods. This is what makes a page programmable: once the tree exists, your code can find a node, read it, change it, add new nodes, or delete them, and the browser immediately re-renders the result.

This topic is the foundation for everything else in Module 12. Before you can create elements with createElement(), restyle them through classList, or wire up event listeners, you need a clear mental picture of the tree and of how JavaScript reaches into it. You will also want to be comfortable with the distinction between a static page (HTML as authored and served) and a dynamic page (HTML as modified at runtime by script), because that distinction explains why the DOM — not your source file — is the thing you are actually manipulating.

As you watch, look for three things. First, how the presenter maps HTML markup onto tree nodes — parent, child, and sibling relationships. Second, which methods are used to select elements (getElementById, querySelector, querySelectorAll, and the older collection-returning methods) and what each one actually returns. Third, how content is read and written through properties such as textContent, innerText, and innerHTML, and what the practical differences between them are. Keep your browser's developer console open and try each selection and modification yourself on a small test page.

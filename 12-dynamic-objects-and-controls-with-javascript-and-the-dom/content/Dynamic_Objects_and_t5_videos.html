Introduction

Creating elements with JavaScript only gets you halfway to an interactive page. The other half is listening: deciding which user or browser actions your code should react to, and writing the functions that run when those actions occur. The modern way to do this is addEventListener, a method available on every DOM node (and on window and document) that connects an event type such as click, input, keydown, submit, or scroll to a handler function.

Along the way you will meet the event object that the browser passes into every handler. It carries details like event.target (the element that actually triggered the event), event.currentTarget (the element the listener is attached to), event.type, key and pointer information, and methods such as preventDefault() and stopPropagation(). You will also learn that events travel through the DOM tree in two phases — capturing down from the root, then bubbling back up — and that the third argument to addEventListener (true/false, or an options object with capture, once, and passive) lets you control that behavior. Because listeners can accumulate and leak, removeEventListener and the once option matter for clean code.

The payoff for this module is event delegation: instead of attaching a listener to every button in a list you build dynamically, you attach one listener to a stable parent and use event.target to figure out what was clicked. As you watch the videos below, pay attention to three things: the exact syntax of addEventListener and its options, how the speaker uses the event object to identify the source of an event, and why bubbling is what makes delegation possible at all.

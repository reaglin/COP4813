Introduction

Once you can locate an element in the DOM, the next step is changing it. Nearly every interactive feature you will build in this course — toggling a menu, highlighting a form field with an error, updating a counter, showing or hiding a panel — comes down to reading and writing the properties of elements that already exist on the page. JavaScript gives you several parallel routes to do this: attribute methods such as getAttribute(), setAttribute(), hasAttribute() and removeAttribute(); direct property access such as element.id, element.value or element.src; the style object for inline CSS; getComputedStyle() for reading the styles the browser actually applied; className and the classList API for class manipulation; and textContent, innerText, innerHTML and outerHTML for content.

Knowing which route to use matters. Setting a class is usually better than writing a dozen inline style rules, because it keeps presentation in your stylesheet and your logic readable. Reading element.style only returns inline styles, so getComputedStyle() is the tool when you need the value that is actually in effect. And innerHTML is powerful but inserts markup, which raises both performance and security concerns compared with textContent. Changing dimensions and position through the style object (width, height, top, left, transform) follows the same rules and is how animations and drag-style interactions begin.

The three videos below are from a single, consistent tutorial series, so the examples build on each other. As you watch, pay attention to the distinction between an attribute (what is written in the HTML source) and a property (what lives on the JavaScript object), to when the presenter chooses innerHTML versus a text-only property, and to how classList methods add, remove, toggle and test classes without overwriting the ones already there. Try each snippet yourself in the linked Repl or in your browser console — these techniques only stick once you have typed them.

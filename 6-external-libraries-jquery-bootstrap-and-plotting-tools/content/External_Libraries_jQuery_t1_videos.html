Introduction

Almost no modern web project is built entirely from scratch. Instead, developers pull in third-party external libraries — pre-written, tested bundles of JavaScript and CSS such as jQuery, Bootstrap, and Chart.js — so they can focus on their own application logic rather than reinventing common functionality. This topic introduces what those libraries are, where they live, and the two ways you can bring them into a page: downloading the files and hosting them yourself, or linking to a copy hosted on a Content Delivery Network (CDN).

A CDN is a geographically distributed network of servers that stores copies of files close to the people requesting them. For this course, the practical payoff is simple: a single script tag or link tag pointing at a CDN URL gives your page a fully working library with no downloads, no file management, and often faster load times. You will also need to understand the details that make CDN links reliable in production — pinning a specific version number so your site does not break when the library updates, and using integrity (Subresource Integrity) attributes so the browser can verify the file has not been tampered with.

As you watch, pay attention to two things. First, in the CDN videos, focus on the mechanics — edge servers, caching, origin servers, and latency — because that explains why a CDN link usually outperforms a file sitting on your own server. Second, in the jQuery video, notice how the library is introduced and loaded; that is the exact pattern you will repeat for Bootstrap's CSS link tag and Chart.js's script tag, and load order will matter once libraries depend on one another.

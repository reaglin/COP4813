Introduction

Up to this point in the module you have practiced each external library on its own: jQuery for DOM manipulation and events, Bootstrap for responsive layout and components, and Chart.js for data visualization. This topic brings them together. A realistic web page rarely uses just one library — it uses a layout framework, a DOM/AJAX helper, and a charting tool all on the same page, each loaded from a CDN or a local file, each with its own dependencies and its own expectations about when it runs.

The practical issues are mostly about order and structure. Scripts must load so that dependencies arrive before the code that uses them (jQuery before jQuery plugins, Bootstrap's JavaScript bundle after its dependencies, Chart.js before any chart-rendering code), initialization code should run after the DOM is ready, and the project folder itself should be organized so that CSS, JavaScript, vendor files, and markup stay separate and predictable. You also need to watch for conflicts: two libraries claiming the same global name, duplicate versions of jQuery, or a plugin written for an older version than the one you loaded.

The videos below are walkthroughs of working projects rather than isolated feature demos. As you watch, pay attention to the head and footer of each page: which libraries are included, in what sequence, and from where. Notice how a jQuery event (a button click, a date selection, a form submit) triggers a request for data, and how that returned data is then handed to both a table and a chart. The third video steps back to the bigger picture of how front-end code fits with a backend and a database, which is the context in which these multi-library pages usually live.

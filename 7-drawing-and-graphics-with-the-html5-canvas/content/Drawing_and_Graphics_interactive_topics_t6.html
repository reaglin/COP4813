Drawing and Manipulating Images

▶

One of the most powerful capabilities of the HTML5 Canvas API is the ability to draw, scale, and crop raster images directly onto the canvas surface. Whether you are building a photo editor, a sprite-based game, an image carousel, or a data visualization tool that overlays graphics on photographs, understanding how to work with images on the canvas is fundamental. This topic covers every stage of that process: loading images safely, drawing them at their natural size, resizing them to fit specific dimensions, cropping out regions of interest, and combining cropping with scaling for advanced effects like sprite sheets and thumbnail generation. Along the way we will also address practical concerns like cross-origin restrictions, animation performance, and the timing problem that catches nearly every beginner off guard.

Loading an Image for Canvas Use

Before any image can be drawn onto a canvas, the browser must fully download and decode that image file. The standard way to manage this in JavaScript is to create an Image object programmatically, assign its source, and then defer all drawing code until the image's onload event fires.

const canvas = document.getElementById('myCanvas');
const ctx = canvas.getContext('2d');

const img = new Image();
img.onload = function () {
    // Safe to draw — the image is fully loaded
    ctx.drawImage(img, 0, 0);
};
img.src = 'photo.jpg'; // Setting src AFTER onload is assigned

It is critically important to attach the onload handler before setting the src property. If you set src first, the browser may begin fetching the image immediately, and if it is already cached or loads extremely fast, the onload event can fire before your handler is even registered — meaning your drawing code will never execute. By wiring up the handler first, you guarantee that no matter how quickly the image arrives, your code will run.

Attempting to call ctx.drawImage() before the image has loaded is one of the most common beginner mistakes. The result is that nothing appears on the canvas, or in some browsers an error is thrown. The image object exists in JavaScript memory, but its pixel data has not yet been decoded, so the canvas has nothing to paint. The onload callback solves this completely by acting as a gate: drawing logic simply cannot run until the image is ready.

Modern code often uses the equivalent Promise-based pattern, which integrates well with async/await:

function loadImage(src) {
    return new Promise((resolve, reject) => {
        const img = new Image();
        img.onload = () => resolve(img);
        img.onerror = () => reject(new Error(`Failed to load image: ${src}`));
        img.src = src;
    });
}

async function main() {
    const canvas = document.getElementById('myCanvas');
    const ctx = canvas.getContext('2d');
    const img = await loadImage('photo.jpg');
    ctx.drawImage(img, 0, 0);
}

main();

This pattern is especially useful when you need to load multiple images before beginning to draw, since you can use Promise.all() to wait for all of them simultaneously.

Basic drawImage Usage

Once an image is loaded, the simplest way to place it on the canvas is the two-coordinate form of drawImage:

ctx.drawImage(img, x, y);

This draws the image at position (x, y), where x is the horizontal offset from the left edge of the canvas and y is the vertical offset from the top edge. The image is rendered at its natural size — that is, the actual pixel dimensions of the image file itself. If your image file is 800 × 600 pixels and you draw it at (0, 0), it will occupy the top-left 800 × 600 pixels of the canvas.

img.onload = function () {
    // Draw the image starting at the top-left corner of the canvas
    ctx.drawImage(img, 0, 0);

    // Draw the same image offset 50px right and 30px down
    ctx.drawImage(img, 50, 30);
};

The canvas coordinate system always places the origin (0, 0) at the top-left corner, with the x-axis increasing to the right and the y-axis increasing downward. This is the same convention used throughout the 2D Canvas API for shapes, text, and paths. Parts of the image that extend beyond the canvas boundaries are simply clipped and not rendered — the canvas never expands to accommodate content drawn outside its bounds.

The ctx variable is the 2D rendering context, obtained once from the canvas element:

const ctx = canvas.getContext('2d');

This context object is the gateway to all drawing operations. It maintains state such as the current transformation matrix, fill and stroke styles, global opacity, and composite operations — all of which affect how images are drawn.

Scaling Images with drawImage

To draw an image at a size different from its natural dimensions, use the five-argument form of drawImage:

ctx.drawImage(img, x, y, width, height);

Here, width and height specify the exact pixel dimensions the image should occupy on the canvas. The browser scales the image to fit those dimensions, stretching or shrinking as necessary.

img.onload = function () {
    // Draw the image at half its natural size
    ctx.drawImage(img, 0, 0, img.naturalWidth / 2, img.naturalHeight / 2);

    // Draw the image at a fixed 200x150 box, ignoring natural proportions
    ctx.drawImage(img, 0, 0, 200, 150);

    // Draw the image stretched to fill the entire canvas
    ctx.drawImage(img, 0, 0, canvas.width, canvas.height);
};

A key point: the canvas API does not automatically preserve the aspect ratio. If you supply a width and height that differ from the original proportions, the image will appear distorted — squashed or stretched. To maintain the aspect ratio, you must calculate the proportional dimension yourself:

const targetWidth = 300;
const aspectRatio = img.naturalWidth / img.naturalHeight;
const targetHeight = targetWidth / aspectRatio;

ctx.drawImage(img, 0, 0, targetWidth, targetHeight);

Alternatively, to fit an image within a bounding box while preserving its aspect ratio (letterboxing), you can use the following approach:

function drawImageContained(ctx, img, x, y, boxWidth, boxHeight) {
    const scale = Math.min(boxWidth / img.naturalWidth, boxHeight / img.naturalHeight);
    const scaledWidth = img.naturalWidth * scale;
    const scaledHeight = img.naturalHeight * scale;
    // Center the image within the box
    const offsetX = x + (boxWidth - scaledWidth) / 2;
    const offsetY = y + (boxHeight - scaledHeight) / 2;
    ctx.drawImage(img, offsetX, offsetY, scaledWidth, scaledHeight);
}

Cropping Images with drawImage

The most powerful and complete form of drawImage takes nine arguments:

ctx.drawImage(img, sx, sy, sWidth, sHeight, dx, dy, dWidth, dHeight);

This form allows you to extract a rectangular region from the source image and paint it into a rectangular region on the canvas. The parameters divide into two groups:

Parameter Description
sx X coordinate of the top-left corner of the crop region within the source image (in source pixels)
sy Y coordinate of the top-left corner of the crop region within the source image (in source pixels)
sWidth Width of the crop region within the source image (in source pixels)
sHeight Height of the crop region within the source image (in source pixels)
dx X coordinate on the canvas where the cropped region will be placed
dy Y coordinate on the canvas where the cropped region will be placed
dWidth Width of the destination rectangle on the canvas
dHeight Height of the destination rectangle on the canvas

Consider a concrete example: you have a 1200 × 800 pixel photograph, and you want to display only the right half of the image (starting at x=600) in a 300 × 200 area at the top-left corner of your canvas:

img.onload = function () {
    ctx.drawImage(
        img,
        600, 0,    // sx, sy — start 600px in from the left of the source
        600, 800,  // sWidth, sHeight — the crop region is 600x800 px in the source
        0, 0,      // dx, dy — place it at the canvas origin
        300, 200   // dWidth, dHeight — scale it down to 300x200 on the canvas
    );
};

The source coordinates sx, sy, sWidth, and sHeight are always measured in the image's own pixel coordinate space, not the canvas coordinate space. If the image has been scaled using CSS or if the canvas has a device pixel ratio other than 1, this distinction matters — you always reference the image's intrinsic pixels for the source rectangle.

Combining Cropping and Scaling

The real utility of the nine-argument form emerges when you deliberately mismatch the source and destination sizes. This is the mechanism that powers sprite sheets, image zoom effects, and thumbnail generation.

Magnifying a region (zoom effect): Pick a small source crop and map it to a large destination rectangle.

img.onload = function () {
    // Zoom into a 100x100 pixel region of the source image
    // and display it at 400x400 on the canvas
    ctx.drawImage(
        img,
        200, 150,  // crop starts at (200, 150) in the source
        100, 100,  // crop is 100x100 px in the source
        0, 0,      // place at canvas origin
        400, 400   // stretch to 400x400 — 4× magnification
    );
};

Miniaturizing a region (thumbnail effect): Pick a large source crop and map it to a small destination rectangle.

img.onload = function () {
    // Compress the entire image into a 80x60 thumbnail in the top-left
    ctx.drawImage(
        img,
        0, 0,
        img.naturalWidth, img.naturalHeight,
        0, 0,
        80, 60
    );
};

Sprite sheet animation: A sprite sheet is a single image file that contains multiple animation frames arranged in a grid. By changing the source crop coordinates each frame, you cycle through different poses without loading multiple image files. Suppose each frame is 64 × 64 pixels and there are 8 frames arranged horizontally:

const FRAME_WIDTH = 64;
const FRAME_HEIGHT = 64;
let currentFrame = 0;

function drawFrame() {
    ctx.clearRect(0, 0, canvas.width, canvas.height);

    ctx.drawImage(
        spriteSheet,
        currentFrame * FRAME_WIDTH, 0,  // move horizontally through the sheet
        FRAME_WIDTH, FRAME_HEIGHT,
        100, 100,  // draw at (100, 100) on the canvas
        FRAME_WIDTH, FRAME_HEIGHT
    );

    currentFrame = (currentFrame + 1) % 8;
    requestAnimationFrame(drawFrame);
}

spriteSheet.onload = drawFrame;
spriteSheet.src = 'character.png';

This technique dramatically reduces HTTP requests compared to loading individual frame images and is the standard approach in 2D browser game development.

Practical Considerations for Image Drawing

Cross-Origin Resource Sharing (CORS): When you draw an image from a different domain onto a canvas, the canvas becomes tainted. A tainted canvas blocks methods that read pixel data back out of the canvas, such as toDataURL(), toBlob(), and getImageData(). This is a deliberate browser security measure to prevent scripts from reading pixel data from cross-origin images without the server's permission.

To resolve CORS restrictions, two conditions must be met: the image server must include the header Access-Control-Allow-Origin: * (or a specific origin), and you must set the crossOrigin property on the Image object before assigning its src:

const img = new Image();
img.crossOrigin = 'anonymous'; // Must be set BEFORE src
img.onload = function () {
    ctx.drawImage(img, 0, 0);
    // Now toDataURL() and getImageData() will work
    const dataURL = canvas.toDataURL();
};
img.src = 'https://example-cdn.com/photo.jpg';

If the server does not include the appropriate CORS header, setting crossOrigin will actually cause the request to fail, because the browser will make a CORS preflight request that the server is not prepared to satisfy. Images served from the same origin never have this problem.

Clearing the canvas before redrawing: In animation loops and interactive applications, images are typically redrawn many times per second. If you draw a new image frame on top of a previous one without first clearing the canvas, old frames bleed through — an artifact known as ghosting. Always clear the relevant portion of the canvas before drawing a new frame:

function animate() {
    ctx.clearRect(0, 0, canvas.width, canvas.height); // Wipe everything
    ctx.drawImage(img, playerX, playerY);
    requestAnimationFrame(animate);
}

clearRect(x, y, width, height) fills the specified rectangle with fully transparent pixels, effectively erasing it. You can clear the entire canvas by passing 0, 0, canvas.width, canvas.height, or you can clear only the region that changed for a minor performance optimization in complex scenes.

Caching the Image object: Creating a new Image object and setting its src inside a render loop is a serious performance mistake. Each time you assign a new src, the browser must initiate a network request (even if cached, this involves cache lookup overhead), decode the image file, and allocate memory. Instead, create and load the image once — outside the loop — and simply reference the already-decoded object on every frame:

// WRONG — creates a new Image every frame
function badAnimate() {
    const img = new Image();
    img.src = 'sprite.png'; // New request every frame!
    img.onload = () => ctx.drawImage(img, x, y);
    requestAnimationFrame(badAnimate);
}

// CORRECT — image loaded once, reused on every frame
const img = new Image();
img.onload = function () {
    requestAnimationFrame(goodAnimate); // Start loop only after load
};
img.src = 'sprite.png';

function goodAnimate() {
    ctx.clearRect(0, 0, canvas.width, canvas.height);
    ctx.drawImage(img, x, y); // Uses already-decoded image data
    requestAnimationFrame(goodAnimate);
}

Keeping in mind these fundamentals — proper load sequencing, the three forms of drawImage, the mechanics of cropping and scaling, and the practical pitfalls around CORS, clearing, and caching — gives you a complete and robust foundation for all image-related canvas work, from simple photo display to complex frame-by-frame sprite animation.

Introduction to the HTML5 Canvas Element

Introduction

The HTML5 canvas element gives you a blank rectangular drawing surface on a webpage that you control entirely from JavaScript. Unlike HTML elements such as divs or images, the canvas itself holds no content you can style or inspect in the DOM — it is a bitmap you paint onto by calling drawing commands. That single idea shapes everything else in this module: if you want a shape on screen, your code has to draw it, and if you want it to change, your code has to draw it again.

In this topic you will see the full startup sequence: placing a canvas tag in your markup with width and height attributes, giving it an id, selecting it in JavaScript with something like document.getElementById, and calling getContext("2d") to obtain the rendering context object that exposes the drawing API. You will also meet the canvas coordinate system, where the origin sits at the top-left corner and the y-axis increases downward — a detail that trips up many beginners and that matters later when you map mouse positions into canvas space.

As you watch, pay attention to a few specifics: why the width and height should be set as HTML attributes rather than only in CSS, what exactly getContext returns and why the context (not the canvas) owns the drawing methods, and how the presenter checks that the setup worked before drawing anything complex. Try typing the setup code yourself alongside the video rather than only watching it.

Drawing Basic Shapes

Introduction

The HTML5 canvas element is a blank drawing surface that does nothing on its own. Everything you see on a canvas is produced by JavaScript: you select the canvas element from the DOM, ask it for a 2D rendering context, and then issue drawing commands against that context. This topic walks through the first and most important set of those commands — the ones that put rectangles, circles, arcs, lines, and multi-sided shapes on the screen.

Along the way you will meet the two ideas that organize nearly all canvas drawing. The first is the path: you begin a path, move to a starting point, add segments or arcs, and then close it. The second is the fill-versus-stroke distinction: fillStyle and strokeStyle decide the colors, and fill() and stroke() decide whether a shape is painted solid or outlined. Rounded rectangles are a good test case because they combine straight line segments with arcs in a single path.

As you watch the videos below, pay attention to the setup sequence that appears at the start of every example — getElementById followed by getContext('2d') — and notice the order in which styling properties are set relative to the drawing calls. Also watch for coordinates: the canvas origin is the top-left corner, x increases to the right and y increases downward, and arcs are measured in radians rather than degrees. Getting comfortable with these conventions now will make the later work on text, images, animation, and mouse interaction much easier.

Drawing and Manipulating Images

Introduction

So far in this module you have drawn shapes, paths, and text using the Canvas 2D context. This topic adds raster images to that toolkit. The key method is drawImage, which takes an image source and paints its pixels onto the canvas at coordinates you choose. Because the canvas is immediate-mode, an image you draw becomes part of the canvas bitmap: it cannot be moved or restyled later, only cleared and redrawn.

The first practical hurdle is loading. An image file is fetched asynchronously, so calling drawImage before the file has finished downloading silently draws nothing. The standard pattern is to create an Image object, assign a handler to its onload (or a 'load' event listener), set the src, and do the drawing inside that handler. From there, drawImage has three forms: three arguments to place an image at a point, five arguments to place and scale it into a destination rectangle, and nine arguments to crop a source rectangle out of the image and then scale that crop into a destination rectangle — the basis of sprite sheets and image tiling.

As you watch, pay attention to where the drawing call sits relative to the load handler, how the argument list changes as scaling and cropping are added, and how the source rectangle is measured in the image's own pixel dimensions rather than canvas coordinates. Also note practical issues such as image aspect ratio, canvas size versus CSS size, and the fact that images loaded from other domains can taint the canvas.

Foundations of Interactive Canvas Graphics

Introduction

So far in this module you have used the Canvas 2D context to draw shapes, paths, text, and images. Those drawings are static: once a pixel is painted, the canvas has no memory of the shape that produced it. Interactive canvas work builds on that fact. Because canvas is an immediate-mode surface, anything that needs to move or respond to the user must be modeled in JavaScript variables, cleared from the screen, and drawn again from scratch on every frame.

This topic brings together three ideas. First, event handling: attaching listeners such as mousedown, mousemove, or click to the canvas element and converting the event's page coordinates into canvas coordinates, usually with getBoundingClientRect() and an awareness of the canvas's CSS size versus its drawing-buffer size. Second, the animation loop: using requestAnimationFrame so redraws are synchronized with the browser's refresh rate instead of being guessed at with setInterval. Third, code structure: keeping setup, state, input handling, and rendering in separate functions so the program stays readable as it grows.

The videos below approach these ideas from different angles — a particle system that manages many moving objects, a focused explanation of requestAnimationFrame, and a small complete interactive project. As you watch, pay attention to where each author stores state, where the clearing happens, and what runs once at setup versus what runs on every frame. Those distinctions are the heart of this topic, and they carry over directly to whatever interactive canvas project you build.

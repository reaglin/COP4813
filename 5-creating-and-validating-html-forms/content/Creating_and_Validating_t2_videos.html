Introduction

Forms are the main way users send data to a web application. Every search box, login screen, checkout page, and survey is built from the same small set of HTML elements: the form element itself, plus input, select, option, textarea, button, and label. What makes forms interesting is that a single element — input — changes behavior entirely based on its type attribute, producing anything from a simple text box to a date picker, a color swatch, a file chooser, or an invisible field that carries data the user never sees.

In this course, this topic is the foundation for everything that follows in the module. Before you can validate input, choose between GET and POST, or wire up the Constraint Validation API in JavaScript, you need to know which control to reach for and how to mark it up correctly. Choosing the right input type is also your first accessibility and usability decision: type="email" and type="tel" change the on-screen keyboard on mobile devices, radio buttons communicate mutually exclusive choices, and a properly associated label makes a control usable with a screen reader or by clicking the text next to it.

As you watch the videos below, pay attention to a few recurring details: how the name attribute (not the id) determines what gets submitted, how label and id are paired, how radio buttons in the same group share a name while checkboxes usually do not, and how select/option differ from a list of radios. Try pausing and rebuilding each example yourself — a registration or contact form that uses text, password, email, radio, checkbox, select, textarea, and submit is a good practice target.

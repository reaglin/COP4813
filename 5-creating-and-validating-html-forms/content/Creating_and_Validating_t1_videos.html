Introduction

HTML forms are the primary way that web pages collect information from people: a search box, a login screen, a checkout page, and a survey are all forms. At its core, a form is a container element, <form>, that groups a set of controls (text boxes, checkboxes, radio buttons, drop-down lists, buttons) and defines what should happen when the user submits them. Two attributes on the <form> element do most of that work: action, which names the URL that will receive the data, and method, which says how the data travels (most commonly GET or POST).

In this course, forms are the bridge between the browser and server-side processing. Before you can validate input or handle it in application code, you need a clear mental model of form structure: the <form> wrapper, the controls inside it, the name attribute that labels each piece of submitted data, the <label> elements that connect text to controls, and the submit button that triggers the request. Getting this structure right from the start makes later work on accessibility and validation far easier.

As you watch the videos below, pay attention to a few things: how the <form> tag is opened and closed and what sits inside it, where action and method appear and how they are described, how each input is given a name and an associated label, and how different input types change what the user sees and what gets sent. Try typing along with at least one example rather than only watching.

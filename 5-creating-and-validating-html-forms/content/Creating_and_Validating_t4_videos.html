Introduction

A form is only useful if the data it collects actually reaches somewhere. That delivery is controlled by a small set of attributes on the form element: action tells the browser where to send the data, method tells it how to send it (most commonly GET or POST), and enctype tells it how the data should be encoded on the way. Together these three attributes determine the shape of the HTTP request your server receives.

In this course the distinction matters because you will build both the front end and the code that consumes the submitted data. GET appends name/value pairs to the URL as a query string, which makes it visible, bookmarkable, cacheable, and limited in length — fine for searches and filters, wrong for passwords or anything that changes state. POST places the data in the request body, which suits larger payloads, sensitive values, and file uploads. File uploads in particular require enctype set to multipart/form-data, while the default application/x-www-form-urlencoded handles ordinary text fields.

As you watch the videos below, pay attention to three things: what the URL looks like after submission, what the request actually contains, and which attribute combination the presenter uses for each scenario. Also notice how submission is triggered — a submit button, the Enter key inside a text input, or JavaScript — because later in this module you will intercept that moment to run validation.

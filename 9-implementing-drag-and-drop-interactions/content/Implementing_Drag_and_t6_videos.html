Introduction

Up to this point you have examined the HTML5 Drag and Drop API one event at a time. In this topic you put the pieces together and build a complete interactive component — typically a sortable list or a Kanban-style board — where items can be picked up, dragged across containers, and dropped into a new position. The work begins before any code: planning what the component must do, deciding which elements are draggable, which are drop targets, and what data each dragged item carries.

From there you build the markup (draggable="true", container and item structure, data attributes for identifiers), wire up dragstart to stash an identifier on the dataTransfer object, use dragover with preventDefault() to declare a valid drop zone, and finish in drop by moving or reordering the DOM nodes. Just as important is what happens behind the visible interface: the underlying data model — the array or object that represents your list or board — must stay in sync with the DOM, or the component will look correct but behave incorrectly on save, refresh, or re-render. Finally, because pointer-based dragging excludes keyboard and screen-reader users, you add keyboard alternatives, ARIA attributes, and clear visual affordances.

The three videos below approach the same problem from different angles: native browser API, a framework component library, and a reusable framework-level abstraction. While watching, track three things — where state is stored, how each event handler contributes to the interaction lifecycle, and what the implementation does (or fails to do) for users who are not using a mouse. Being able to compare a hand-written implementation to a library-provided one is useful even if your project uses only vanilla JavaScript.

A compact walkthrough of drag-and-drop in plain JavaScript that, based on its title and description, covers both dragging HTML elements around the page and dragging files into the browser, and also mentions using a plugin for added functionality. Why this video

How These Videos Support the Learning Outcomes

Together these videos reinforce the module outcomes at the point where they come together in a real build. The vanilla JavaScript walkthrough and the Svelte action video both work directly with the native events and the DataTransfer object, supporting MO1, MO2, and MO3 by showing which handler does what and why preventDefault() on dragover matters. The Angular CDK video and the multi-list reordering pattern it demonstrates support MO4, since a working sortable or Kanban component requires that the DOM and the underlying data arrays update in step. None of the videos is a dedicated accessibility lesson, so for MO5 you should watch each implementation critically and note where keyboard operation, focus handling, and ARIA attributes would need to be added before the component could be considered complete.

Introduction to HTML5 Drag and Drop

Introduction

Drag and drop is one of the few interaction patterns that users already understand before they ever see your interface: grab something, move it, let go. HTML5 includes a native Drag and Drop API that lets you build this behavior without an external library. The API is built from a small set of pieces — the draggable attribute that marks an element as movable, a sequence of events fired on the source and on the potential drop target, and the DataTransfer object that carries data (and dragged files) from the source to the target.

In this course the API matters because it sits at the intersection of DOM events, data handling, and user experience. Sortable lists, Kanban boards, file upload zones, image galleries, and shopping-cart builders are all common use cases you may be asked to build. The API is supported broadly in modern desktop browsers, but behavior differs across browsers and is weak on touch devices, so understanding compatibility limits is part of learning the topic.

As you watch the videos below, pay attention to three things: which element each event listener is attached to (the dragged item versus the drop zone), where and why preventDefault() is called, and how data moves through dataTransfer. Notice also the distinction between dragging elements already on the page and dragging files in from the operating system — both use the same API but handle data differently.

Making Elements Draggable

Introduction

Drag and drop feels natural to users, but browsers do not grant it automatically. In HTML5, an element becomes a drag source only when you mark it with the draggable attribute and then attach JavaScript that responds when the drag begins. This topic focuses on that first half of the interaction: preparing the source element, recognizing which element the user grabbed, wiring up a dragstart listener, and placing information into the dataTransfer object so a drop target can later retrieve it.

This matters in COP4813 because every later piece of the module depends on a correctly configured source. If the draggable attribute is missing, if dragstart never fires, or if nothing is stored in dataTransfer, the dragover and drop handlers you write afterward will have nothing meaningful to work with. Getting the source right also sets up the visual feedback users rely on — the class changes, opacity shifts, and drag images that signal "this item is moving."

As you watch the videos below, pay close attention to three things: where the draggable attribute is declared (markup versus JavaScript), how the developer identifies the element being dragged inside the event handler (event.target, a stored reference, or an id), and what exactly gets passed to dataTransfer.setData. Also notice what the videos do not cover — keyboard access and ARIA announcements for assistive technology — since native drag and drop is mouse-oriented by default and accessibility must be added deliberately by you.

Handling the dragstart Event

Introduction

Every drag-and-drop interaction begins with a single moment: the user presses the mouse on a draggable element and starts to move it. That moment fires the dragstart event on the source element, and it is your one reliable opportunity to say what is being dragged, what data travels with it, and how the browser should visually represent the operation. If dragstart is not handled correctly, everything that follows — dragover, drop, and your DOM updates — has nothing meaningful to work with.

In this topic you will attach a dragstart listener (either in JavaScript with addEventListener or through the HTML draggable attribute plus an inline handler), then work with the event's dataTransfer property. The DataTransfer object is the small clipboard that rides along with the drag: you call setData() with a format string such as "text/plain" and a payload (often an element's id), set effectAllowed to describe whether the operation is a copy, move, or link, and optionally call setDragImage() to replace the default ghost image the browser generates.

As you watch the videos, pay attention to three things: where the listener is attached (the draggable source, not the drop target), exactly what value is passed to setData() and how that same value is later read back during the drop, and how the presenter makes the drag visually obvious — for example by adding a CSS class on dragstart and removing it later. Noticing those patterns now will make the dragover and drop topics much easier.

Handling the drop Event

Introduction

The drop event is where a drag-and-drop interaction finally pays off. It fires on the drop target when the user releases the mouse button over an element that has been designated a valid target, and it is your opportunity to read the data that was stashed during dragstart and act on it. Because browsers have default behaviors for dropped content (such as opening a dragged link or file), your drop handler almost always begins with event.preventDefault() before doing anything else.

In this topic you will work through the full sequence: attaching a drop listener to the target, suppressing default browser behavior, calling event.dataTransfer.getData() with the same format string you used in setData(), using the retrieved value (typically an element id) to locate the dragged element with document.getElementById(), and then updating the DOM — usually with appendChild() or insertBefore() — so the element visually moves into its new container. Finally, you clean up any visual feedback, such as highlight classes or opacity changes added during dragover and dragstart, so the interface returns to a neutral state.

The heart of all of this is DOM manipulation: showing, hiding, moving, and restyling elements with JavaScript. The video below focuses on that underlying skill. As you watch, pay attention to how elements are selected, how classes and styles are toggled, and how those same techniques would let you update a drop target and remove leftover highlighting after a successful drop.

Building an Interactive UI Component

Introduction

Up to this point you have examined the HTML5 Drag and Drop API one event at a time. In this topic you put the pieces together and build a complete interactive component — typically a sortable list or a Kanban-style board — where items can be picked up, dragged across containers, and dropped into a new position. The work begins before any code: planning what the component must do, deciding which elements are draggable, which are drop targets, and what data each dragged item carries.

From there you build the markup (draggable="true", container and item structure, data attributes for identifiers), wire up dragstart to stash an identifier on the dataTransfer object, use dragover with preventDefault() to declare a valid drop zone, and finish in drop by moving or reordering the DOM nodes. Just as important is what happens behind the visible interface: the underlying data model — the array or object that represents your list or board — must stay in sync with the DOM, or the component will look correct but behave incorrectly on save, refresh, or re-render. Finally, because pointer-based dragging excludes keyboard and screen-reader users, you add keyboard alternatives, ARIA attributes, and clear visual affordances.

The three videos below approach the same problem from different angles: native browser API, a framework component library, and a reusable framework-level abstraction. While watching, track three things — where state is stored, how each event handler contributes to the interaction lifecycle, and what the implementation does (or fails to do) for users who are not using a mouse. Being able to compare a hand-written implementation to a library-provided one is useful even if your project uses only vanilla JavaScript.

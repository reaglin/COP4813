Introduction

Animation in the browser is the controlled change of visual properties over time: an element fades in, a menu slides open, a chart bar grows, a loading spinner rotates. Behind every one of these effects is the browser's rendering pipeline, which recalculates styles, lays out elements, paints pixels, and composites layers — ideally fast enough to produce a new frame roughly every 16.7 milliseconds (60 frames per second). Understanding that pipeline is what separates animation that feels polished from animation that stutters.

Animation matters in this course because it is a user experience tool, not decoration. Motion communicates state changes, directs attention, confirms that an action registered, and makes transitions between views feel continuous rather than abrupt. Used carelessly, it does the opposite: it distracts, delays interaction, and drains battery on mobile devices.

There are two primary approaches you will work with. CSS-based animation (transitions and @keyframes) is declarative — you describe the start and end states and let the browser handle the frames, often on the compositor thread for free performance. JavaScript-driven animation (typically using requestAnimationFrame) is imperative — you compute values frame by frame, which costs more but buys you control over physics, user input, and dynamic conditions. As you watch these videos, pay attention to three things: which properties are being animated, who is deciding the value of each frame, and what the speaker says about when to pick one approach over the other.

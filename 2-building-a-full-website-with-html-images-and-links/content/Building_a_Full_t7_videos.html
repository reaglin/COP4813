Introduction

Up to this point in the module you have practiced individual HTML skills: writing semantic elements, placing images, and creating links. This topic asks you to combine those skills into a single, working multi-page website. That means deciding what pages your site needs, naming files and folders consistently, repeating the same semantic structure and navigation menu on every page, adding images with meaningful alt text, and wiring the pages together with relative links while pointing outward with absolute URLs.

This matters because real websites are judged as a whole, not as isolated code snippets. A visitor notices immediately when a navigation link is broken, an image fails to load, or one page looks structurally different from the rest. Planning your folder layout before you start writing HTML, and testing every link and image when you finish, is what turns a pile of files into a site.

The two videos below approach the idea of a complete site from different angles. The first reviews the HTML content elements you will place inside your pages; the second shows a no-code site builder so you can see how pages, navigation, and media fit together conceptually before you hand-code the same ideas. While watching, pay attention to structure and organization rather than to any single tag: ask yourself how each page relates to the others, where files would live on disk, and what you would need to check before calling the site finished.

Module 1: 1 -GitHub, GitHub Pages, and Your First HTML Page

Topics

Introduction to GitHub

Students learn what GitHub is and why it is used, then create and configure a personal GitHub account to get started.
  • What is GitHub? — GitHub is a web-based platform that allows developers to store, manage, and share their code online.
  • Why GitHub is Used — GitHub serves as both a storage hub for code and a collaboration tool for developers working individually or in teams.
  • Creating a GitHub Account — To get started with GitHub, you first need to create a free personal account on the GitHub website.
  • Choosing a Username — Your GitHub username is a permanent part of your public identity on the platform and will appear in links to your projects and website.
  • Configuring Your GitHub Profile — After creating your account, you can configure your profile to add basic information that helps others identify you and your work.

Creating Your First Repository

Students set up a new GitHub repository, understanding key concepts such as repository naming, visibility settings, and initialization options.
  • Navigating to the New Repository Page — Creating a repository begins by locating the correct option inside your GitHub account.
  • Naming Your Repository — Choosing a clear, descriptive repository name is an important first step that identifies your project on GitHub.
  • Setting Repository Visibility — GitHub allows you to control who can see your repository through visibility settings selected at creation time.
  • Initializing the Repository — GitHub offers optional initialization files that give your repository useful starting content and structure right away.
  • Confirming Repository Creation — Once all options are configured, submitting the form finalizes the creation of your new repository.

Deploying with GitHub Pages

Students enable GitHub Pages on their repository and learn how GitHub automatically publishes web content to a live public URL.
  • What is GitHub Pages? — GitHub Pages is a free hosting service built into GitHub that automatically publishes files from your repository as a live website accessible to anyone on the internet.
  • Enabling GitHub Pages on Your Repository — You activate GitHub Pages through your repository's Settings tab, selecting the branch and folder GitHub should use as the source for your published site.
  • Understanding the Automatic Publishing Process — Once GitHub Pages is enabled, GitHub automatically detects changes pushed to your selected branch and rebuilds and republishes your site without any manual steps.
  • Your Live Public URL — GitHub Pages assigns your site a unique public URL based on your GitHub username and repository name, making your site immediately shareable.
  • Verifying Your Deployment — After enabling GitHub Pages, you should confirm that your site is live and displaying the correct content by visiting the published URL in a browser.

Writing Your First HTML Document

Students create a basic 'Hello, World' HTML file, learning the essential structure of an HTML document including the doctype, head, and body elements.
  • What is an HTML Document? — An HTML document is a plain text file that a web browser reads and renders as a web page. It uses a set of tags to define the structure and content of the page.
  • The DOCTYPE Declaration — Every HTML document begins with a DOCTYPE declaration that tells the browser which version of HTML is being used. For modern web development, the declaration is simply <!DOCTYPE html>.
  • The Root <html> Element — The <html> element is the root element that wraps all content in the document. Everything else in the file sits inside the opening <html> and closing </html> tags.
  • The <head> Element — The <head> element contains metadata about the document — information that is not displayed directly on the page but is important for the browser and search engines.
  • The <body> Element — The <body> element contains all the visible content of the web page — everything the user sees in the browser window. It follows the closing </head> tag.
  • Writing 'Hello, World' — The classic first program in any language, 'Hello, World,' is achieved in HTML by placing a simple text element inside the body. A heading tag such as <h1> is a clear and common choice.
  • Putting It All Together: The Complete Basic Structure — A minimal, valid HTML document combines the DOCTYPE, the <html> root, the <head> with a title, and the <body> with visible content — all nested in the correct order.

Publishing and Verifying Your Live Page

Students commit and push their HTML file to GitHub and confirm the page renders correctly on their GitHub Pages site.
  • Staging and Committing Your HTML File — Before your file can be published, you must stage it and create a commit that records the change in your repository's history.
  • Pushing Your Commit to GitHub — Pushing sends your local commit to the remote GitHub repository, making the file available online for GitHub Pages to serve.
  • Understanding GitHub Pages Build Delay — After pushing, GitHub Pages requires a brief processing period before your changes appear at the live URL.
  • Navigating to Your GitHub Pages URL — Every GitHub Pages site is assigned a public URL based on your GitHub username and repository name.
  • Verifying the Page Renders Correctly — Confirming that your HTML page displays as expected is the final step in the publishing workflow and validates your entire setup.
  • The Commit–Push–Verify Workflow — The sequence of committing, pushing, and verifying forms the core development loop you will repeat throughout the course whenever you update your site.

Understanding the Development Workflow

Students review the end-to-end workflow of editing code locally, committing changes to GitHub, and seeing updates reflected on a live site, establishing the pattern used throughout the course.
  • The Three Stages of the Local-to-Live Pipeline — The core development workflow moves code through three distinct stages: editing locally, saving changes to GitHub, and viewing the result on a live site.
  • Editing Code Locally — Local editing means writing and modifying your HTML files on your own computer using a code editor before any changes go online.
  • Committing Changes to GitHub — A commit is a saved snapshot of your changes, and pushing that commit sends it from your local machine to your GitHub repository.
  • Seeing Updates on the Live Site — After a commit is pushed, GitHub Pages rebuilds the site automatically and the updates become visible at your public URL within moments.
  • Why This Workflow Is Used Throughout the Course — This edit-commit-publish cycle is the repeating pattern that every future module will follow, so understanding it now builds the foundation for all subsequent work.

Module 2: 2 -Building a Full Website with HTML, Images, and Links

Topics

Introduction to Multi-Page Website Structure

Overview of how a full website is organized across multiple pages and the role HTML plays in defining that structure. Establishes the foundational concepts learners will build upon throughout the module.
  • What Is a Multi-Page Website? — A multi-page website is a collection of individual HTML files that work together to form a cohesive online presence.
  • The Role of HTML in Defining Structure — HTML is the foundational language that defines the structure and content of every page within a website.
  • Core Components of an HTML Page — Every HTML page shares a standard set of components that give it a valid, well-formed structure.
  • Semantic Markup and Its Importance — Semantic HTML uses meaningful tags that describe the role of content rather than just its appearance.
  • How Pages Connect: The Concept of Internal Linking — Internal links are the mechanism that ties individual HTML pages together into a navigable website.
  • Planning a Website Before Writing Code — Before creating any HTML files, outlining the site's pages and how they relate to each other saves time and prevents structural problems.

Semantic HTML Markup

Explores the use of semantic HTML elements such as header, nav, main, section, article, and footer to create meaningful, accessible page structure. Explains why semantic markup matters for readability and search engines.
  • What Is Semantic HTML? — Semantic HTML uses elements whose names clearly describe their purpose and the type of content they contain, rather than using generic containers like div or span for everything.
  • The <header> and <nav> Elements — The <header> element represents introductory content at the top of a page or section, while <nav> marks a block of navigation links.
  • The <main>, <section>, and <article> Elements — These three elements organize the primary body content of a page into meaningful regions, from the overall main area down to individual standalone pieces of content.
  • The <footer> Element — The <footer> element contains closing information for its nearest sectioning ancestor, such as copyright notices, contact details, or secondary navigation.
  • Semantic Markup and Accessibility — Screen readers and other assistive technologies rely on semantic elements to create landmark regions, allowing users with disabilities to navigate a page efficiently.
  • Semantic Markup and Search Engine Optimization (SEO) — Search engine crawlers parse HTML to understand a page's content hierarchy, and semantic elements provide clear signals about which content is most important.
  • Structuring a Full Page with Semantic Elements — Combining all semantic elements into a coherent page layout results in a document that is readable, maintainable, and accessible from the very first line of HTML.

Embedding Images in HTML

Covers how to use the img element to embed images into web pages, including setting source paths, alt text, and sizing attributes. Addresses best practices for image formats and accessibility.
  • The img Element — The HTML `<img>` element is used to embed images directly into a web page. It is a self-closing (void) element, meaning it does not require a closing tag.
  • Setting the Source Path with src — The `src` attribute tells the browser where to find the image file, accepting either a relative or an absolute URL as its value.
  • Providing Alt Text for Accessibility — The `alt` attribute supplies alternative text that describes an image, which is displayed when the image cannot load and read aloud by screen readers.
  • Controlling Image Size with width and height — The `width` and `height` attributes can be added to the `<img>` element to specify the display dimensions of an image in pixels.
  • Choosing the Right Image Format — Selecting an appropriate image format is critical for balancing visual quality, file size, and browser compatibility.
  • Image Accessibility Best Practices — Beyond alt text, several additional practices ensure that images are accessible and inclusive for all users.

Creating Hyperlinks

Introduces the anchor element and its attributes for building both internal and external hyperlinks. Explains how linking connects pages and resources to form a cohesive website experience.
  • The Anchor Element — The anchor element, written as <a>, is the fundamental HTML tag used to create hyperlinks that connect pages and resources.
  • The href Attribute — The href (hypertext reference) attribute is placed inside the opening <a> tag to specify the destination URL or file path of the link.
  • External Hyperlinks — External hyperlinks point to pages or resources hosted on other websites, using a full absolute URL as the href value.
  • Internal Hyperlinks — Internal hyperlinks connect pages within the same website using relative file paths, allowing users to navigate between your own HTML files.
  • The target Attribute — The target attribute controls where the linked page or resource opens when the user clicks the hyperlink.
  • Linking as the Foundation of Website Structure — Hyperlinks are what bind individual HTML pages and resources together, creating the interconnected structure that defines a website.

Internal Navigation and Site Linking

Focuses on constructing internal links that connect multiple pages within the same website, including relative file paths and navigation menus. Demonstrates how to build a consistent navigation structure across pages.
  • Understanding Relative File Paths — Relative file paths define the location of a linked page in relation to the current HTML file, making them the foundation of internal site navigation.
  • Creating Basic Internal Links with the Anchor Tag — The HTML anchor element <a> with an href attribute pointing to a relative path is the core mechanism for linking pages within the same website.
  • Building a Navigation Menu Structure — A navigation menu groups multiple internal links together, typically using an unordered list inside a <nav> element to create a clear, accessible site menu.
  • Maintaining Consistent Navigation Across Pages — Placing the same navigation menu HTML on every page of the site ensures users always have access to the same links regardless of which page they are viewing.
  • Organizing Multi-Page Site File Structure — A logical file and folder organization is essential for internal linking to work correctly and for the site to remain manageable as it grows.
  • Linking to Page Sections with Fragment Identifiers — Fragment identifiers allow an internal link to navigate directly to a specific section within a page by targeting an element's id attribute.

External Links and Web Resources

Explains how to link to external websites and online resources using absolute URLs and appropriate anchor attributes such as target and rel. Covers security and user experience considerations for external linking.
  • Absolute URLs for External Links — External links point to resources on other websites and require a complete, absolute URL including the protocol, domain, and path.
  • Opening Links in a New Tab with target — The target attribute on an anchor element controls where the linked resource opens when a user clicks the link.
  • Security Risks of target="_blank" and the rel Attribute — Opening external links in a new tab with target="_blank" introduces a security vulnerability known as reverse tabnapping, which can be mitigated using the rel attribute.
  • Communicating Link Destination to Users — Good user experience requires that visitors know before clicking whether a link will take them to an external site or open a new tab.
  • Linking to Specific Online Resources — External links can point to a wide variety of online resources, including other web pages, documents, images, and media hosted on different domains.
  • The rel Attribute for Link Relationships — The rel attribute describes the relationship between the current page and the linked resource, providing semantic meaning for browsers and search engines.

Bringing It All Together: Building a Complete Website

Guides learners through assembling all module concepts into a cohesive, functional multi-page website using semantic markup, images, and links. Reinforces skills through a practical, end-to-end project exercise.
  • Planning Your Multi-Page Website Structure — Before writing a single line of code, successful websites begin with a clear plan that maps out pages, content, and navigation flow.
  • Setting Up a Consistent File and Folder Organization — A well-organized project folder ensures that HTML files, images, and other assets are easy to locate and reference with correct relative paths.
  • Applying Semantic Markup Across Every Page — Semantic HTML elements give meaning to page content, improving accessibility, SEO, and code readability throughout your entire site.
  • Embedding Images with Descriptive Alt Text — Images enhance visual appeal and communication, and every image must include an alt attribute that accurately describes its content for accessibility.
  • Creating Internal Links Between Pages — Internal hyperlinks connect your site's pages together, forming the navigation system that allows visitors to move through your website.
  • Adding External Links and Best Practices — External links direct users to resources on other websites and should be implemented with care to maintain a good user experience and site credibility.
  • Reviewing and Testing Your Complete Website — Thorough testing is the final step before considering a project complete, ensuring all pages, links, and images work correctly together as a cohesive whole.

Module 3: 3 -Styling Web Pages with CSS

Topics

Introduction to CSS

An overview of what Cascading Style Sheets are and how they work alongside HTML to control the visual presentation of web pages. Students learn how to link CSS to their HTML documents using inline, internal, and external stylesheet methods.
  • What is CSS? — CSS, or Cascading Style Sheets, is a stylesheet language used to control the visual presentation of HTML documents.
  • How CSS Works with HTML — CSS works alongside HTML by targeting HTML elements and applying visual rules to them.
  • Inline CSS — Inline CSS is applied directly to a single HTML element using the style attribute within the opening tag.
  • Internal CSS — Internal CSS is written inside a <style> element placed within the <head> section of an HTML document.
  • External CSS — External CSS stores all styles in a separate .css file that is linked to one or more HTML documents.
  • Choosing the Right Method — Each of the three CSS methods — inline, internal, and external — has appropriate use cases depending on the scope and scale of styling needed.

CSS Selectors

Exploration of the different types of CSS selectors including element, class, ID, and combination selectors used to target specific HTML elements. Students learn how specificity and the cascade determine which styles are applied when rules conflict.
  • Element Selectors — Element selectors target HTML elements directly by their tag name, applying styles to every instance of that element on the page.
  • Class Selectors — Class selectors target elements that share a specific class attribute, allowing the same styles to be applied to multiple elements regardless of their tag type.
  • ID Selectors — ID selectors target a single, unique element on a page using the element's id attribute, making them ideal for styling one-of-a-kind components.
  • Combination Selectors — Combination selectors allow developers to target elements based on their relationship to other elements or by combining multiple conditions, enabling precise styling control.
  • CSS Specificity — Specificity is a scoring system browsers use to determine which CSS rule takes precedence when multiple rules target the same element and property.
  • The Cascade — The cascade is the algorithm CSS uses to resolve conflicts between rules, considering origin, specificity, and source order to decide which styles are ultimately applied.

The Box Model

A foundational concept explaining how every HTML element is treated as a rectangular box with content, padding, border, and margin areas. Students learn how to manipulate these properties to control spacing and sizing of elements on a page.
  • What Is the Box Model? — Every HTML element on a web page is treated by the browser as a rectangular box. This box is made up of four distinct areas that together form the CSS Box Model.
  • The Content Area — The content area is the innermost part of the box, where the actual text, images, or other media of an element are displayed.
  • Padding — Padding is the space between the content area and the element's border. It creates breathing room inside the element, pushing the content away from the edges.
  • Border — The border wraps around the padding and content areas, forming a visible or invisible boundary around the element. It sits between the padding and the margin.
  • Margin — Margin is the outermost layer of the box model, creating space outside the element's border to separate it from neighboring elements.
  • The box-sizing Property — By default, the 'width' and 'height' properties in CSS apply only to the content area, meaning padding and border are added on top of that size. The 'box-sizing' property changes how the total size of an element is calculated.
  • Inspecting the Box Model with DevTools — Modern browser developer tools provide a visual diagram of the box model for any selected element, making it easy to inspect and debug spacing and sizing issues.

Typography and Colors

Covers CSS properties for styling text including font family, size, weight, line height, and text alignment to improve readability. Students also learn how to apply colors using named values, hex codes, and RGB notation to both text and backgrounds.
  • Font Family — The font-family property specifies the typeface used to display text on a web page.
  • Font Size and Weight — Font size controls how large text appears, while font weight controls its thickness or boldness.
  • Line Height and Text Alignment — Line height and text alignment are key properties that directly affect the readability and layout of text blocks.
  • Applying Colors with Named Values and Hex Codes — CSS allows colors to be specified using human-readable named values or precise hexadecimal codes.
  • Applying Colors with RGB Notation — RGB notation defines colors by specifying the intensity of red, green, and blue channels as numeric values from 0 to 255.
  • Styling Text Color and Background Color — CSS provides two distinct properties for applying color: one for text and one for the background of an element.

CSS Layout Techniques

An introduction to modern CSS layout methods including Flexbox and basic positioning to arrange elements on a web page. Students apply these techniques to structure multi-section page layouts in a visually organized way.
  • Understanding CSS Layout Flow — By default, browsers arrange HTML elements using normal document flow, where block elements stack vertically and inline elements sit side by side.
  • Introducing Flexbox — Flexbox is a one-dimensional CSS layout model that arranges items in a row or column, making it easy to align and distribute space among elements in a container.
  • Aligning and Justifying Flex Items — Flexbox provides two primary axes — the main axis and the cross axis — each controlled by dedicated alignment properties.
  • Controlling Individual Flex Items — Properties applied directly to flex children let you override container-level alignment and control how each item grows or shrinks.
  • CSS Positioning — The position property removes elements from normal flow or adjusts their placement relative to a reference point, enabling overlapping and fixed UI elements.
  • Structuring Multi-Section Page Layouts — Combining Flexbox and positioning allows you to build organized, multi-section page layouts such as headers, sidebars, main content areas, and footers.

Styling a Complete Web Page

Students bring together all learned CSS concepts to apply cohesive visual styling to the websites they built in the previous lesson. This capstone topic reinforces best practices for writing clean, organized CSS stylesheets.
  • Linking Your Stylesheet to Your HTML Page — Before any CSS can be applied, the external stylesheet must be properly connected to the HTML document using a link element in the head section.
  • Organizing Your CSS Stylesheet — A well-organized stylesheet groups related rules together and uses comments to label each section, making the code easier to read and maintain.
  • Applying Typography Across the Page — Consistent typography ties a web page together visually by establishing a clear hierarchy of headings, body text, and supporting content.
  • Using Color Cohesively — A cohesive color scheme unifies all sections of a web page and reinforces the overall visual identity of the site.
  • Styling Layout and Spacing with the Box Model — Proper use of margin, padding, and width controls how each element occupies space on the page and how sections relate to one another visually.
  • Styling Navigation and Interactive Elements — Navigation links and buttons are the primary interactive elements on most pages and should receive deliberate styling that signals their purpose to users.
  • Reviewing and Refining the Finished Stylesheet — Once all styles are applied, a final review pass ensures the stylesheet is clean, consistent, and free of redundant or conflicting rules.

Module 4: 4 - Introduction to the Document Object Model (DOM)

Topics

What is the DOM?

Introduces the Document Object Model as a concept, explaining what it is and why it exists as a bridge between HTML documents and JavaScript programming.
  • Defining the DOM — The Document Object Model (DOM) is a programming interface that represents an HTML document as a structured, programmable object.
  • Why the DOM Exists — The DOM exists to bridge the gap between a static HTML document and dynamic programming languages like JavaScript.
  • How Browsers Create the DOM — When a browser loads an HTML page, it parses the markup and builds the DOM in memory as a structured object model.
  • The DOM as a Tree Structure — The DOM organizes the objects created from an HTML document into a hierarchical tree, reflecting the nested nature of HTML markup.
  • The DOM as an Interface Between HTML and JavaScript — The DOM acts as the critical interface — or bridge — that allows JavaScript code to interact with the content and structure of an HTML document.

How Browsers Parse HTML into the DOM

Explains the process browsers use to read HTML markup and construct the DOM tree, including how the parsing sequence affects script execution and page rendering.
  • What Happens When a Browser Receives HTML — When a browser receives an HTML file from a server, it begins reading the raw markup text and converting it into a structured, in-memory representation called the DOM.
  • Tokenization: Breaking HTML into Meaningful Pieces — The first stage of parsing is tokenization, where the browser's HTML parser scans the character stream and groups characters into discrete tokens such as opening tags, closing tags, and text content.
  • Building the DOM Tree from Tokens — Once tokens are produced, the browser's tree construction algorithm arranges them into a hierarchy of parent and child nodes, forming the DOM tree.
  • How Parser-Blocking Scripts Affect Parsing — When the parser encounters a <script> tag without special attributes, it pauses HTML parsing, downloads the script if needed, executes it, and only then continues building the DOM.
  • The defer and async Attributes — The defer and async attributes on a <script> tag instruct the browser to download the script without blocking the HTML parser, though they differ in when the script actually executes.
  • The DOMContentLoaded Event and Parse Completion — Once the browser has finished parsing the HTML and constructing the DOM tree, it fires the DOMContentLoaded event on the document object, signaling that the DOM is ready to be accessed.
  • Parsing Order and Its Impact on Page Rendering — Because the browser parses HTML top to bottom, the order in which elements and resources appear in the markup directly influences how quickly content becomes visible to the user.

The DOM Tree Structure

Describes the hierarchical node-based structure of the DOM, covering the relationships between document, element, text, and attribute nodes.
  • What Is the DOM Tree? — The DOM (Document Object Model) represents an HTML document as a hierarchical, tree-shaped structure that browsers construct when they parse HTML.
  • The Document Node — The document node sits at the very top of the DOM tree and serves as the entry point to the entire document.
  • Element Nodes — Element nodes correspond directly to HTML tags such as <html>, <body>, <p>, and <div>, forming the primary structural building blocks of the DOM tree.
  • Text Nodes — Text nodes contain the actual textual content found between HTML tags and are always leaf nodes — they cannot have children of their own.
  • Attribute Nodes — Attribute nodes represent the attributes defined on HTML elements, such as id, class, href, or src, and are associated with their parent element node.
  • Parent, Child, and Sibling Relationships — The DOM tree is defined by the relationships between nodes: every node (except the document root) has exactly one parent, may have multiple children, and may have sibling nodes at the same level.
  • How Browsers Build the DOM Tree from HTML — Browsers parse HTML source code top-to-bottom and incrementally construct the DOM tree, translating each tag and piece of text into the appropriate node type.

Selecting DOM Elements

Covers the core vanilla JavaScript methods used to query and retrieve elements from the DOM, such as getElementById, querySelector, and querySelectorAll.
  • What Is DOM Selection? — DOM selection is the process of using JavaScript to locate and retrieve specific HTML elements from the DOM tree so they can be read or manipulated programmatically.
  • getElementById — getElementById is the most direct selection method, retrieving a single element that carries a specific 'id' attribute value.
  • querySelector — querySelector retrieves the first element in the document that matches a given CSS selector string, offering flexible single-element selection.
  • querySelectorAll — querySelectorAll extends the querySelector approach to return every element in the document that matches the given CSS selector, collected as a NodeList.
  • Scoped Selection with Element References — Selection methods can be called on any Element object, not just on 'document', allowing you to search only within a specific part of the DOM tree.
  • Reading and Verifying Selection Results — After selecting an element, developers should verify the result before operating on it to prevent null-reference errors that crash scripts.

Manipulating DOM Elements

Explains how to read and modify element properties, attributes, styles, and text content using JavaScript once elements have been selected.
  • Reading and Writing Text Content — JavaScript provides properties to read and update the visible text inside a DOM element once it has been selected.
  • Modifying HTML Attributes — Attributes such as href, src, id, and alt can be read and changed programmatically through dedicated DOM methods.
  • Working with the classList API — The classList property exposes a set of methods that make adding, removing, and toggling CSS classes straightforward without overwriting existing ones.
  • Directly Modifying Inline Styles — Each DOM element exposes a style property that maps to its inline CSS declarations, allowing individual style rules to be set via JavaScript.
  • Reading Computed Styles — To determine the actual rendered style of an element—including styles inherited from stylesheets—use the getComputedStyle method.
  • Getting and Setting Element Properties — Beyond attributes, DOM elements expose a range of JavaScript properties that directly reflect characteristics of the element object itself.

Adding and Removing DOM Nodes

Demonstrates how to dynamically create new elements, insert them into the DOM tree, and remove existing nodes using JavaScript methods.
  • Creating New Elements with createElement() — JavaScript provides the document.createElement() method to dynamically generate new HTML elements in memory before they are added to the page.
  • Setting Content and Attributes on New Nodes — Before inserting a newly created element, you typically populate it with text content or set attributes to make it meaningful and functional.
  • Inserting Nodes with appendChild() and append() — Once an element is created, it must be inserted into the existing DOM tree using methods such as appendChild() or the newer append().
  • Inserting Nodes at Specific Positions with insertBefore() and insertAdjacentElement() — When precise placement within a parent is required, JavaScript offers methods to insert nodes at specific positions rather than always at the end.
  • Removing Nodes with removeChild() and remove() — JavaScript allows existing DOM nodes to be deleted from the document tree using removeChild() on the parent or the simpler remove() method called directly on the target element.
  • Cloning Nodes with cloneNode() — The cloneNode() method creates a copy of an existing DOM node, which can then be inserted elsewhere in the tree without affecting the original element.
  • Replacing Nodes with replaceChild() and replaceWith() — Existing nodes can be swapped out for new ones using replaceChild() on the parent element or the modern replaceWith() method called on the node being replaced.

Module 5: 5 - Creating and Validating HTML Forms

Topics

Introduction to HTML Forms

An overview of the purpose and structure of HTML forms, including the form element and how forms facilitate user input and data submission.
  • What Is an HTML Form? — An HTML form is a structured section of a web page that allows users to enter and submit data to a server or client-side script.
  • The <form> Element — The <form> element is the root HTML tag that wraps all form controls and defines how and where the form data will be submitted.
  • Key Form Attributes: action and method — The action and method attributes on the <form> element control where the form data is sent and how it is transmitted.
  • Purpose of Forms in Collecting User Input — HTML forms serve as the primary interface for gathering structured information from users and passing it to an application for processing.
  • Overview of Form Structure — A well-structured HTML form organizes its controls using semantic elements such as labels, fieldsets, and legends to improve clarity and accessibility.

Form Input Types and Elements

  • Listener Options: once, passive, and capture — The third parameter of addEventListener accepts an options object that fine-tunes listener behavior beyond simply attaching a callback.
  • Removing Event Listeners with removeEventListener — To prevent memory leaks and unintended behavior in dynamic UIs, event listeners should be explicitly removed when they are no longer needed using removeEventListener.
  • Event Delegation for Dynamic Elements — Event delegation is a pattern that attaches a single listener to a stable ancestor element to manage events from child elements that may be added or removed dynamically at runtime.

  • Encapsulating Controls for Reusability — Well-designed JavaScript UI controls are encapsulated as reusable functions or classes, making them easy to instantiate multiple times with different configurations.

Game Design Fundamentals

  • Scoping the Project Appropriately — Choosing a game concept that matches the available time and technical skills is a critical design decision.

Canvas Drawing for Games

Students apply HTML5 Canvas drawing techniques to render game elements such as characters, obstacles, and backgrounds onto the browser screen.
  • Setting Up the Canvas Element — The HTML5 Canvas element provides a drawable surface within the browser that games use as their visual output.
  • Drawing Background Layers — A game background provides the visual environment and is typically drawn first so all other elements appear on top of it.
  • Rendering Character Sprites — Characters are the player-controlled or animated figures drawn onto the canvas to represent the main actors in the game.
  • Drawing Obstacles and Game Objects — Obstacles and collectibles are additional drawn elements that create challenge and interactivity within the game world.
  • Clearing and Redrawing the Canvas — Because games update visually many times per second, the canvas must be cleared before each frame is redrawn to prevent visual artifacts.
  • Using Coordinates and the Canvas Grid — The canvas uses a pixel-based coordinate system where (0, 0) is the top-left corner, with x increasing to the right and y increasing downward.

Animation and the Game Loop

Students implement a continuous game loop using requestAnimationFrame to drive smooth animation and update game state on every frame.
  • What Is a Game Loop? — A game loop is a continuous cycle that updates game state and redraws the screen many times per second to create the illusion of motion and interactivity.
  • Introducing requestAnimationFrame — requestAnimationFrame is a browser API that schedules a callback function to run just before the browser paints the next frame, typically 60 times per second.
  • Writing the Core Loop Function — The loop function is called on every frame and serves as the heartbeat of the entire game, coordinating all updates and drawing in the correct order.
  • Updating Game State Each Frame — The update step advances all game objects — such as player position, enemy movement, and score — based on logic and elapsed time before anything is drawn.
  • Delta Time and Frame-Rate Independence — Delta time is the number of milliseconds elapsed since the last frame, and multiplying movement values by it ensures objects move at a consistent speed on any device.
  • Starting and Stopping the Loop — The loop must be explicitly started once when the game begins, and it can be stopped by cancelling the scheduled animation frame when the game ends or pauses.

Event Handling and Player Input

Students wire up keyboard, mouse, or touch event listeners to capture player input and translate it into meaningful in-game actions.
  • Attaching Event Listeners to the Document or Canvas — Event listeners are registered using addEventListener() on the document or the canvas element to begin capturing player input.
  • Reading Keyboard Input — Keyboard events expose properties like event.key and event.code that identify which key was pressed, released, or held down.
  • Reading Mouse Input — Mouse events provide cursor coordinates and button state, allowing players to aim, click, or drag within the game canvas.
  • Handling Touch Input for Mobile Play — Touch events mirror mouse events but support multiple simultaneous contact points, making them essential for mobile-compatible games.
  • Translating Raw Input into Game Actions — Raw event data must be mapped to meaningful in-game behaviors such as moving a character, firing a projectile, or pausing the game.
  • Preventing Default Browser Behavior — Many keys and gestures trigger built-in browser behaviors that can disrupt gameplay and must be suppressed with event.preventDefault().

Game Logic and State Management

Students manage core game mechanics such as scoring, collision detection, win and loss conditions, and tracking the overall state of the game.
  • Tracking Game State — Game state refers to all the variables that describe the current condition of the game at any moment, such as whether the game is running, paused, or over.
  • Implementing a Scoring System — A scoring system rewards players for successful actions and provides feedback on their performance throughout the game.
  • Collision Detection — Collision detection determines when two game objects occupy the same space, triggering gameplay consequences such as losing a life or earning a point.
  • Win Conditions — A win condition is a specific goal the player must achieve to successfully complete the game or a level.
  • Loss Conditions and Lives — Loss conditions end the game when the player fails to meet survival requirements, such as running out of lives or time.
  • Resetting and Restarting the Game — Providing a reset mechanism lets players try again without reloading the page, improving the overall user experience.

  • Establishing the Project Structure — A well-organized file and code structure is the foundation of a complete, maintainable browser game.
  • Combining Drawing and Animation Systems — The visual layer of the game requires merging Canvas drawing routines with the animation loop established in earlier lessons.
  • Wiring Up Event Handling and Player Input — Player interaction is connected to the game by attaching the event listeners built in previous lessons to the unified game loop.
  • Implementing the Unified Game Loop — The game loop is the central engine that calls update and render in sequence every frame, tying all subsystems together.
  • Integrating Game Logic and Win/Lose Conditions — All collision detection, scoring, and state-transition logic developed earlier must be consolidated into the update phase of the game loop.
  • Testing and Debugging the Complete Project — Once all components are assembled, systematic testing ensures the integrated game behaves correctly as a whole.
  • Embedding and Presenting the Finished Game — The final step is ensuring the completed game runs reliably in a browser and is ready to be shared or submitted as a finished project.

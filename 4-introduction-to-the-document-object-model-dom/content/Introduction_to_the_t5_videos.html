Introduction

Once you can select an element from the DOM, the next step is to change it. Every element node exposes properties and methods that let JavaScript read and rewrite what the user sees: the text inside an element, the markup it contains, its attributes (such as src, href, id, or data-* values), the CSS classes applied to it, and its inline style declarations. This topic covers that toolkit — textContent and innerText, innerHTML and outerHTML, getAttribute/setAttribute, the classList API (add, remove, toggle, contains), the style object, and getComputedStyle for reading the styles the browser actually resolved.

This matters in COP4813 because almost every interactive feature you build — showing a validation message, highlighting a selected row, disabling a button, swapping an image — is some combination of these operations. It also matters for correctness and safety: writing to innerHTML parses a string as HTML and can introduce security and performance problems, while textContent treats the same string as plain text. Knowing which property to reach for is part of writing professional front-end code.

As you watch, pay attention to three things. First, the difference between properties that read or write text and those that read or write markup, and when each is appropriate. Second, the distinction between an element's inline style (what you set through .style) and its computed style (what the browser resolves from all stylesheets). Third, why toggling a CSS class is usually preferable to setting many inline styles one at a time — it keeps presentation in your CSS and behavior in your JavaScript.

Introduction

When a browser loads an HTML file, it does not simply display the text: it reads the markup and builds an in-memory model of the page called the Document Object Model. That model is organized as a tree. A single document node sits at the root, element nodes (such as html, body, div, and p) branch out beneath it, text nodes hold the actual words you see on screen, and attribute nodes carry information like id, class, and src that belongs to an element.

Understanding this structure matters because every piece of JavaScript you write later in this course depends on it. Selecting an element, changing its text, adding a class, or inserting a new node all assume you can picture where that node sits in the tree and what is above, below, and beside it. The vocabulary of parent, child, and sibling is how the DOM API lets you move from one node to another, and properties such as parentElement, children, childNodes, firstChild, nextSibling, and previousSibling are the tools for that movement.

As you watch the videos below, keep a specific question in mind: for a given line of HTML, what nodes does the browser actually create? Pay attention to the difference between an element node and the text node inside it, notice how whitespace and line breaks in your source can appear as text nodes, and watch for the distinction between properties that return all node types and those that return elements only. Sketching a small HTML snippet as a tree on paper while you watch is the fastest way to make this concrete.

Introduction

When a browser loads a web page, it does not simply display the HTML file as text. It reads (parses) the markup and builds an in-memory model of the document: a structured collection of objects that represent every element, attribute, and piece of text on the page. That model is the Document Object Model, or DOM. Because it is made of objects, JavaScript can read it, search it, and change it while the page is running.

This topic is the conceptual foundation for the rest of the module and for much of the rest of the course. Before you can select elements, change styles, or add new content with code, you need a clear mental picture of what you are actually working with: a tree of nodes rooted at the document object, with parent, child, and sibling relationships that mirror the nesting of your HTML tags. You should also understand why the DOM exists at all — it is a standardized interface that lets a scripting language talk to a document that was written in a markup language.

As you watch the videos below, look for three things. First, the distinction between your HTML source file and the DOM the browser builds from it, since they are related but not identical. Second, the vocabulary of the tree: document, element nodes, text nodes, attributes, parent and child. Third, how JavaScript reaches into that tree through the document object. Try opening your browser's developer tools alongside the videos and inspect a simple page of your own so the abstract tree becomes something you can see.

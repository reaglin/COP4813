Introduction to CSS

Introduction

HTML gives a web page its structure and meaning, but on its own it says almost nothing about how that content should look. Cascading Style Sheets (CSS) is the language that handles presentation: colors, fonts, spacing, borders, backgrounds, and layout. Browsers read your HTML, then apply the CSS rules you have written to decide how each element is painted on the screen.

In this topic you will meet the basic anatomy of a CSS rule — a selector that targets elements, followed by declarations made of property and value pairs — and the three ways to attach CSS to an HTML document. Inline CSS uses the style attribute on a single element, internal CSS places a style block in the document head, and external CSS keeps rules in a separate .css file linked with a link tag. All three work, but they differ sharply in reusability and maintainability, which is why professional projects overwhelmingly favor external stylesheets.

As you watch the videos below, pay attention to three things: the exact syntax used in each method, where the code physically lives relative to the HTML, and the reasoning each instructor gives for preferring one method over another. Try typing the examples into your own practice file rather than only watching — seeing a style take effect in your browser is the fastest way to make the cascade feel concrete.

CSS Selectors

Introduction

CSS selectors are the part of a style rule that answers the question "which elements should this styling apply to?" Every rule you write begins with a selector, so learning the selector vocabulary — element (type) selectors, class selectors, ID selectors, and the various ways of combining them — is the foundation for everything else you will do with CSS in this module.

Once you can target elements precisely, a second question arises: what happens when two or more rules try to style the same element in different ways? That is where specificity and the cascade come in. Specificity is a scoring system that ranks selectors (ID selectors outrank class selectors, which outrank element selectors), and the cascade adds rules about source order, origin, and importance. Understanding both lets you debug "why isn't my style applying?" instead of guessing.

As you watch the videos below, pay attention to three things: the exact syntax for each selector type (the dot for classes, the hash for IDs, spaces and commas between selectors mean very different things), when it is appropriate to use a class versus an ID, and how specificity is calculated when rules conflict. Try typing the examples into your own stylesheet and changing them — selector behavior is much easier to remember once you have broken a rule and fixed it yourself.

The Box Model

Introduction

Every element you place on a web page is rendered as a rectangular box, even when its edges are invisible. The CSS box model describes the four layers of that box: the content area where text and images live, the padding that cushions the content, the border that wraps around the padding, and the margin that separates the box from its neighbors. Understanding these layers is what turns guesswork about spacing into deliberate, predictable design decisions.

This topic matters in COP4813 because almost every layout problem you will face later — aligning sections, spacing navigation links, sizing cards in a grid — comes back to the box model. A related detail, the box-sizing property, determines whether the width you set applies only to the content area (content-box, the default) or includes padding and border (border-box). Many developers set border-box globally precisely because it makes sizing far easier to reason about.

As you watch, pay attention to three things: how shorthand properties such as margin: 10px 20px map to the top, right, bottom, and left sides; how margins behave differently from padding (especially around background color and collapsing margins); and how the browser's DevTools box model diagram lets you read the computed content, padding, border, and margin values for any element on a live page. Try reproducing each demonstration in your own test file rather than only watching.

Typography and Colors

Introduction

Typography and color are two of the most visible decisions you make in CSS. Font family, font size, font weight, line height, and text alignment determine whether a block of text is comfortable to read or exhausting to look at, and color determines contrast, mood, and whether a visitor can read your content at all. These are not decorative afterthoughts — they are the properties you will reach for first when you begin styling any page.

In this topic you will work with two related skill sets. The first is text styling: choosing a font stack with font-family, setting size and weight, adjusting line-height for readable spacing between lines, and controlling alignment with text-align. The second is color: naming a color with a keyword like red or steelblue, specifying it precisely with a hex code such as #3366FF, or building it from channel values with rgb() and rgba() notation. You will apply those color values to both the color property (text) and the background-color property (the area behind it).

As you watch the videos below, pay attention to syntax details that trip students up: the comma-separated fallback list in font-family, the unitless number often used for line-height, the # prefix and six-digit pattern of hex codes, and the 0–255 range of each RGB channel. Also notice that every color value in these videos ultimately describes the same thing — the formats are interchangeable, so you can choose the one that fits your workflow. Keep contrast between text color and background color in mind throughout; it is the practical reason these two subtopics are taught together.

CSS Layout Techniques

Introduction

Up to this point in the module you have been styling individual elements — choosing fonts and colors, writing selectors, and adjusting padding, borders, and margins. CSS layout is the next step: deciding where elements sit on the page and how they relate to one another. Every HTML element starts out following the normal document flow, where block-level elements stack vertically and inline elements sit side by side within a line. Layout techniques are the tools you use to change that default behavior deliberately.

This topic focuses on two of the most practical tools for that job. Flexbox is a one-dimensional layout model that lets a container distribute, align, and space its children along a row or a column, and it is the standard way to build navigation bars, card rows, and side-by-side content sections. CSS positioning — static, relative, absolute, fixed, and sticky — lets you take an element partly or fully out of normal flow to pin it in a specific place, such as a sticky header or a badge layered over an image. Together these give you enough control to assemble a multi-section page layout without hacks.

As you watch the videos below, pay attention to the distinction between properties you set on the container (display, flex-direction, justify-content, align-items) and properties you set on individual children (flex-grow, flex-shrink, flex-basis, align-self, and the offset properties top, right, bottom, left). Also notice what each positioning value is measured against — that is the most common source of confusion. Try reproducing the examples in your own stylesheet rather than only watching; layout is much easier to understand when you can change a value and see what moves.

Styling a Complete Web Page

Introduction

So far in this module you have worked with individual CSS concepts: selectors, the cascade, typography properties, color values, the box model, and layout tools like Flexbox. This topic brings all of those pieces together. Instead of styling one element at a time, you will style an entire page from top to bottom using a single external stylesheet, making deliberate choices about fonts, colors, spacing, and navigation so the finished site looks like one coherent design rather than a collection of unrelated rules.

Two habits matter most here. The first is organization: linking your stylesheet correctly with the link element in the head, then grouping rules in a predictable order (resets and base styles, typography, layout, components, interactive states) with comments so you and your teammates can find things later. The second is consistency: reusing a small set of fonts, a limited color palette, and repeatable spacing values so the page feels intentional. Interactive elements such as navigation links, buttons, and form fields need special attention because they have multiple states (normal, hover, focus) that users rely on.

As you watch the videos below, pay attention to three things: how each presenter connects a style rule to the element it targets, how they inspect and verify results in the browser rather than guessing, and how they handle spacing and alignment with box model properties. When you return to your own site, review your stylesheet critically — look for duplicated rules, inconsistent values, and declarations that are not actually doing anything.
